# 阶段三设计与边界 — 2026-11-05 / v0.3.0

用户明确要求服务端模型API Key先留空。实现不申请、不配置、不读取其他OpenAI密钥，不进行任何真实模型调用。

## 架构

延续阶段一二的Next.js静态界面和原CSV/XLSX库，在同一工程新增TypeScript服务端模块。
为保留Windows解压后无需安装依赖的交付方式，服务端通过tsup打包为独立Node模块，随静态预览一起由 `scripts/serve-preview.mjs` 提供同源API。
Next开发模式将 `/api/*` 转发到本机8080；生产交付直接运行打包的Node服务。没有创建Next Route Handler，不把静态HTML冒充服务端接口。

数据流：原始文件在浏览器解析 → 标准化经营字段发送本地服务 → 服务端复用财务纯函数重新计算 → 构造有限的证据映射 → 规则/模型建议 → 指标键与内容校验 → 商品事实确认 → 草稿与七日行动清单。
模型只接收汇总证据、建议上下文和来源摘要；不接收订单ID、原始文件或客户资料。营销模型只使用事实占位符，真实商品事实由服务端在校验后替换。

## API

| 接口 | 输入/输出 |
|---|---|
| GET /api/health | 模式、是否具备完整配置、版本；没有密钥或完整环境变量 |
| GET /api/knowledge | 六张来源知识卡片 |
| POST /api/diagnose | 标准化rows、filters、synthetic、allow_model；返回3—5条建议、证据、缺失项、快照ID、模式和降级原因 |
| POST /api/content | 同上，加facts和recommendation_id；返回三段短视频脚本、商品文案、社交文案、七日行动清单 |

服务端重算指标，不接受客户端提交的利润快照、模型端点或任意附加顶层字段。
POST为JSON、最大8MiB；本机Host白名单、来源检查、每分钟30次接口上限。错误统一包含code/message/details/request_id，不回显上传内容或提供商错误正文。
本地服务默认仅绑定127.0.0.1，无账户或多商户隔离，不作为公网生产服务。

## 模型适配

采用服务器固定配置的OpenAI兼容 `chat/completions` JSON接口，HTTPS、禁止重定向，单次输出上限1800 tokens。
默认Key、base URL、模型名均为空，开关false。即使存在环境变量OPENAI_API_KEY也不读取或使用。
只有完整配置、显式开关、本次用户允许三项同时满足才进入模型分支。
配置缺失、未允许、超时、认证/网络错误或结构/事实校验失败，均保留规则结果与明确状态。
非法输出最多尝试两次；认证/网络/超时错误不重复重试。每次超时默认12秒（可设，限制1—30秒），返回体最大128KiB。
模型自由文本不允许携带数字、认证或疗效断言；财务观察事实由服务器根据真实指标键渲染。模型不能修改基线建议ID、引用不存在的指标或伪造来源。
这是保守的输出约束，不承诺通用语义审查完备；尚无真实模型兼容性与内容质量实测。

## 费用约束与缓存

默认每个本地服务每日最多20次模型传输尝试（含重试、失败），可用LIXIAHE_MODEL_DAILY_CALLS设置0—1000。按北京时间日期重置，服务重启也会重置，是开发环境次数控制，不是人民币账单上限。
仅校验成功的模型结果按请求SHA-256缓存5分钟、最多8项，全部只在本地服务内存中；不缓存原始订单请求。
刷新/清除界面会删除浏览器当前数据；服务器的派生模型缓存至多保留5分钟，关闭服务后全部释放。空Key时没有任何模型缓存或计费请求。

## 商品事实与编辑

规格、产地、特点、配送、名称逐项确认；未确认值输出【待核对】。没有根据地方知识卡片自动填商品产地或认证。
本阶段不接收或审核认证证明，故受保护名称、认证、疗效、极限断言不因勾选而自动通过；具体过滤规则有测试，不能替代人工审核。
允许编辑标题、画面、口播及两种文案。编辑后保留“人工编辑、待复核”标志。复制内容包含草稿标志、来源、占位和七日清单，不自动发布。
更换数据、影响指标的筛选、商品事实或所选建议会清除旧结果；异步请求有取消与序列检查，避免旧响应填入新会话。
